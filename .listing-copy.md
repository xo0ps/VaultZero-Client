# Listing copy (drafts — verify before submitting)

Every claim below is derived from what the package and API actually do.
**Never claim the server cannot see anything.** It stores embeddings (partially invertible to
text), scope labels, sizes, and timestamps. The honest claim is *"it cannot decrypt your
memories"*, not *"it knows nothing"*. Adjust nothing factual without re-checking the source.

## Glama / MCP directory

**Name:** VaultZero

**Short description (≤ 60 chars):**
```
Encrypted long-term memory for AI agents.
```

**Short description (≤ 100 chars, MCP Registry):**
```
Encrypted long-term memory for AI agents: embedded and encrypted on the client.
```

**Long description (~400 chars):**
```
VaultZero gives an AI agent memory that persists across sessions, without handing
the server readable data. Each fact is embedded and encrypted on the client before
it is sent; the server stores ciphertext and vectors and never holds a key.

Two tools: remember_fact stores a fact under a scope you permit, and
recall_context retrieves the nearest memories and decrypts them locally.

The model cannot choose a tenant, a user, or a key, and cannot grant itself a
scope. Recalled text is framed as untrusted data, so a stored instruction cannot
become a command.

Requires a VaultZero API origin and a bearer credential.
```

**Categories / tags:** Developer Tools · AI & Machine Learning · Memory · Security · Data
**Transport:** stdio (local process)
**Runtime:** Python 3.10+, `uvx --from "vaultzero[mcp]" vaultzero-mcp`
**Repository:** https://github.com/xo0ps/VaultZero-Client
**Homepage:** https://vaultzero.cc
**Install:** `pip install "vaultzero[mcp]"` / `uv tool install "vaultzero[mcp]"`
**Docker:** yes — see `Dockerfile`, runs as UID 10001, no pip in the image

**Honest limitations to state plainly if asked:**
- Access is gated: you need a VaultZero API credential. This is not a self-hosted-only server.
- Retrieval quality depends on the embeddings endpoint the operator configures; the built-in
  hashing provider is a development stub with no real semantic search.
- Without `VZ_KEY_STORE_PATH` keys live in memory, so memories become unreadable when the
  process exits.
- This package is the client side. The server component is not in this repository.

## Docker MCP registry

The `Dockerfile` is registry-ready as-is. Build tag suggestion: `xo0ps/vaultzero-mcp`.

Required runtime secrets for the registry entry: `VZ_BASE_URL` (not secret) and
`VZ_CREDENTIAL` (secret). Everything else is optional and documented in `server.json`.

## Do not do

- Do not claim "zero knowledge", "the server can't see anything", or "fully anonymous".
  Embeddings are invertible and are listed in the privacy page as data the server holds.
- Do not claim to be a self-hosted-only or offline server; it talks to the VaultZero API.
- Do not claim general web browsing, search, or file access.
- Do not fabricate download counts, stars, users, or ratings.
- Do not submit to paid tiers for placement.
